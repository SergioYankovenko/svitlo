# Аудит дизайну Android «Світло»

Дата аналізу: **29.10.2026**. База: **1.6.0 / 25**. Мета — відновити повторно застосовні правила з актуального коду та погоджень, зафіксувати розбіжності й створити основу для наступних змін.

Основний результат: [дизайн-система](ANDROID-DESIGN-SYSTEM.md), [токени](android-design-tokens.json), [нативний каталог](catalog.html). Тут наведені походження, спостереження й межі висновків; наведені рекомендації ще не реалізовані.

## 1. Обсяг і метод

Інвентаризовано **74 Kotlin-файли основного коду, 7 544 рядки Kotlin, 27 XML основних ресурсів/manifest**, а також 66 файлів unit/Robolectric та 18 інструментальних Kotlin-файлів. Це кількість файлів, не кількість тестів і не твердження, що кожен транспортний/серверний алгоритм пройшов окремий аудит.

Поглиблений аналіз стосувався всіх основних UI-шляхів: каркас, головна, адреси й майстер, сітка, легенда, підсумки, погода, стрічка, опції, діалоги, власні glyph-и, RemoteViews і стан під час оновлення. Транспорт/модель даних аналізувалися в частині впливу на видимі стани; це не повний аудит безпеки, продуктивності або серверної архітектури.

Метод:

1. Поточний код і ресурси зіставлено з пізнішими Android-вимогами й історією уточнень користувача.
2. Окремо розведено чинний стиль, відкладену мікроправку та випадкові/старі відмінності.
3. Сформовано точні палітри, геометрію, типографіку, компоненти й правила зміни стану.
4. Відібрано **18 нативних PNG** з попередніх перевірок: дві теми, головна, опції, стрічка, п’ять типів діалогів і IME при 200%. Копії побайтові, без ретушування.
5. Для **28 пар кольорів** обчислено контраст непрозорих sRGB за відносною яскравістю.
6. Збережено хеші runtime/ресурсів/тестів до створення опису; після роботи перевіряється їхня незмінність.

У цьому завданні **не** виконувалися нова збірка, встановлення на телефон, розгортання сервера або публікація. Каталог — документація із попередніми знімками, не нове приймання UI на пристроях. Попередні тести використані як історичні джерела з їхніми межами.

## 4. Що вже утворює послідовну систему

- **Палітра:** шість інтерфейсних ролей та чотири типи відключень; світла тема зберігає предметні кольори.
- **Вкладеність форм:** зовнішні 22/24/26 dp, внутрішні 12/13/16 dp з різною функцією. «Усе однакове» тут означає однакові елементи одного рівня.
- **Числова ієрархія:** великі підсумки/температура, середні заголовки, компактні метадані; колір і розмір мають повторювані ролі.
- **Оформлення діалогів:** централізовані header/body/footer, lighter input, soft red cancel, однакові проміжки й строки.
- **Великий текст:** адаптація за компонентом, спільне припасування пар, вертикальні групи; немає одного фіксованого макета для всіх масштабів.
- **Стан не лише кольором:** перекреслення, штрихування/?, рамка поточної години, selected/disabled/expanded для доступності.
- **Стабільне оновлення:** головна/погода зберігають view й scroll при зміні даних; анімується потрібний блок.
- **Предметна чесність:** unknown не перетворюється на power, таймер не вигадує кінець аварії, історична дата не міняє поточний час.
- **Окремий профіль віджетів:** спільний візуальний характер, але фіксована темна палітра й вимірювання RemoteViews.

Ці рішення варто продовжувати, не переосмислювати заново при кожному новому вікні.

Це **черга можливих точкових поліпшень**, а не перелік внесених змін. Пріоритет указує, що перевіряти при наступній відповідній роботі, не означає доведений збій усієї версії.

| Дія / звичайне тло | 10.40 | 5.63 | Базова текстова дія |
| Текст / обраний рядок | 6.74 | 9.65 | Selected фон не погіршує читабельність |
| Hint / поле | 4.78 | 4.72 | Понад 4.5:1, запас невеликий; не знижувати alpha додатково |
| Скасування: текст / тло | 6.61 | 5.05 | М’який червоний лишає читабельний текст |
| Темний glyph / hourly | 7.29 | 7.29 | Значок виразний |
| Темний glyph / planned | 6.44 | 6.86 | Значок виразний |
| Темний glyph / emergency | 5.77 | 5.77 | Значок виразний |
| Темний glyph / unplanned | **2.79** | **3.04** | Темна тема потребує окремого предметного приймання |
| Світлий час / unplanned | 5.10 | 4.69 | Пояснює розділення ролі часу й glyph |

Орієнтири перевірені за первинними джерелами: [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/apps) рекомендує для малого тексту 4.5:1 і ціль 48×48 dp; [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) пояснює мінімум 4.5:1 / 3:1 для великого тексту й винятки декоративного/неактивного вмісту. Не прирівнювати sp до CSS pt буквально. Це локальна перевірка пар, **не сертифікація доступності всього застосунку**.

## 7. Нативні еталони та їхні межі

[native-reference-manifest.json](native-reference-manifest.json) містить для кожного з 18 PNG: тему, fontScale, збірку, джерельний шлях, розміри пікселів і SHA256. Копії в `assets/` роблять довідник незалежним від тимчасових clipboard-файлів користувача.

- **1.6.0 final QA:** опції та повідомлення, API 35, 320 dp, dark/light, стандартний текст. У стрічці QA є тестова версія 1.6.1 і повторені за змістом технічні оголошення з різних fixture ID: це не опублікований новий реліз і не доказ дубліката одного ID.
- **1.5.9 / 24 final touch-flow:** філія, нагадування, confirmation, збережені адреси, керування, IME при 200%, API 26, dark/light. Вони показують погоджений dialog chrome; джерела цього сімейства потім збережені в 1.6.0.
- **Рання 1.5.9:** головна в launcher-матриці, dark/light, стандартний текст. Використовується тільки як історичний зразок композиції; не є піксельним доказом кожної деталі остаточної 1.6.0.

Помилкові/не-PNG записи історичних launcher-прогонів не додано до каталогу. Скриншот launcher сам по собі не доводить доступність усіх віджетів, тому випадкові старі launcher-знімки не включені як поточний еталон віджетів. Їхні точні правила взяті з актуальних RemoteViews, palette, sizing і paging коду.

Каталог дозволяє змінити тему, відфільтрувати сімейство й відкрити повний знімок. Перемикачі каталогу — інструменти документації, їх не додавати в застосунок.

## 8. Матриця наступної перевірки

Вибирати релевантні перевірки за зміною; не перезапускати весь проєкт заради коми в описі. Для нового повторно застосовного компонента важлива така матриця:

| Вісь | Мінімальний набір | Що перевірити |
| --- | --- | --- |
| Платформа | API 26 та 35 або поточний target + релевантний Android 13+ | Нативні метрики, permissions, системні панелі |
| Ширина | 320, 360, 412/414 dp | Немає горизонтального overflow, правильні gap/ellipsis |
| Шрифт | 100%, 150%, 200% | Компонентна адаптація, читабельність, повний доступний зміст |
| Тема | Темна/світла | Токени, contrast, обраний/disabled, відсутність тіней |
| Орієнтація/IME | Портрет/ландшафт, клавіатура відкрита/закрита | Footer і результати доступні, scroll коректний |
| Взаємодія | Дотик по тексту/центру/краях, повторне натискання | Один callback, точний об’єкт, фактичний наступний екран |
| Доступність | Клавіатура/фокус, вузли; ручний TalkBack коли доступний | Немає дублювання, повні назви, реальні стани |
| Дані | Відомі, невідомі, кеш/помилка, довгі назви, пустий результат | Жодних вигаданих станів і втрати останніх коректних даних |
| Життєвий цикл | Перезапуск, recreate, повернення з налаштувань | Не втрачено профіль, дату, scroll і focus |
| Віджети, якщо змінюються | Compact/detail, 1/4/5/10 адрес, малі/великі розміри, reapply | Сталі слоти/вісь, сторінки per ID, bitmap budget, exact tap routing |

Релевантні наявні тести: `Android150UiTest`, `NextPatchUiTest`, `MainNavigationTest`, `ChooserLayoutTest`, `ConfirmationLifecycleTest`, `LegendFit159Test`, `HourTileViewTest`, `UnplannedAppearance156Test`, `WidgetPinPrompt159Test`, `DetailedWidget152Test`, `WidgetRenderTest`, `WidgetLegend158Test`, `ScheduleLabels151Test`, `DisplaySchedule150Test`. Для реального введення — `NativeAddressTouchFlow159`, `NativeUnifiedDialogs159`, `NativePinDialog159`, для layout — `NativeAppLayout159`, для поточних повідомлень — `NativeMessages160`.

Історична базова 1.6.0 має 602 unit/Robolectric тести, 20 native-конфігурацій, lint без Error/Fatal, але **119 Warning** — див. [звіт](../ANDROID-PATCH-1.6.0.md). Вони не запускалися повторно в документаційному завданні. Перевірка програмної семантики не дорівнює ручному прослуховуванню TalkBack; AVD не дорівнює фізичному Xiaomi/Samsung.

## 9. Артефакти цього аналізу та відтворення

Локальні докази: [work/android-design-system-20261029](../../work/android-design-system-20261029/).

- `source-inventory.json` — шляхи, рядки й SHA256 основного коду/ресурсів, кількості тестових файлів.
- `runtime-baseline.json` / `runtime-integrity.json` — перевірка незмінності джерел/ресурсів/тестів, build і кореневих правил.
- `collect_baseline.py` — read-only інвентаризація; записує лише докази цього завдання. Повторний запуск звіряє baseline, не переписує його.
- `build_evidence.py` — перерахунок кольорових пар, побайтове копіювання вибраних PNG й оновлення даних каталогу. Не звертається до пристроїв/мережі; записує тільки `design/` і докази.
- `validation.json` — перевірка локальних посилань/токенів/PNG, структури скіла й незмінності runtime; `catalog-checks.json` — фактично виконані перевірки каталогу.

Токени тут довідкові. Немає нової Gradle-залежності, зміни packageId, versionCode, палітри runtime, міграції Supabase чи опублікованого повідомлення. Наступне погоджене доповнення має оновлювати опис і статус, не переписувати історію попереднього приймання.
