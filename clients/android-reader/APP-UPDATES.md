# Повідомлення про нові версії

## Android 1.6.0 / збірка 25 — опубліковано

29.10.2026 після приймання користувача APK підписано чинним релізним ключем та опубліковано. Серверні міграції/API й експорт GitHub розгорнуті на попередньому погодженому етапі. Старі версії Android продовжують читати сумісний `update.json` schema=1; формат збережений, вміст оновлено для 1.6.0 / 25 із SHA256 підписаного APK. [Перевірки публікації](ANDROID-RELEASE-1.6.0-CHECKS.md), [контракт сервера](backend/android-messages/README.md).

- Три незалежні джерела: сумісний `update.json`, публічний `android-messages.json` через GitHub Pages та захищені адресовані установці повідомлення Supabase. Усі перевіряються **раз на добу після успішного отримання**, при вході та у фоні, незалежно від адреси/оператора/погоди. Інтервал — не гарантія запуску Android за годинником.
- Невдала спроба зберігається окремо від успіху. Мережеві помилки, 408, 429 і 5xx допускають обмежені повтори: 1 хв, 5 хв, 30 хв, 2 год; після вичерпання — наступний добовий цикл. `Retry-After` не обходиться. Окреме збережене фонове пробудження враховує довгий `Retry-After`, навіть коли короткі повтори WorkManager уже завершилися. Некоректний JSON і постійні 4xx не створюють циклу. Попередній коректний кеш зберігається.
- Картки видимі не довше 7 діб від публікації й не довше `expiresAt`. Отримання, перегляд та системний показ мають окремі локальні стани. Перезапуск, зміна адреси й оновлення APK не очищують їх. Встановлена цільова версія прибирає застаріле сповіщення; системний timeout обмежує строк показу.
- На чистому встановленні перемикач **«Нові версії застосунку» вимкнений** до дії користувача; явно збережений вибір чинної установки зберігається. Нових перемикачів, пояснювальних карток дозволу та кнопок налаштування немає. Службові типи керуються дозволом Android і системним каналом «Службові повідомлення»; версії додатково — чинним перемикачем. Заблоковане сповіщення не позначається показаним. Картки й чинні опції доступні також без доданої адреси. Системний дозвіл запитується після увімкнення наявного перемикача; доступ до налаштувань Android залишається через чинний дзвіночок.
- Формат повідомлення про версію збережений за прикладом користувача: «Оновлено · дата час», «Вийшла нова версія …», короткий текст і кнопка «Завантажити». Новий протокол використовує те саме оформлення картки й рядка дій.
- Публічні й приватні повідомлення мають стабільні ID; одна версія з нового повідомлення та `update.json` не створює двох системних сповіщень. Нові повідомлення містять лише текст та обмежені дозволені посилання, без віддалених команд, Firebase або WebSocket.
- Для приватного API повторно використані випадковий ID установки й наявний анонімний Supabase-сеанс, додано окремий випадковий секрет. Сам ID не авторизує читання. У публічний JSON не експортуються приватні повідомлення, ID установок або секрети. Ключ адміністратора в APK відсутній.

Діагностичні тести попереднього механізму підтверджували дефект блокування на 24 години й `Result.success()` після помилки. Їхній успішний результат не є перевіркою виправлення; нова реалізація має окремі регресійні перевірки.

Нижче — контракт і порядок публікації **сумісного маніфесту версії**, який зберігається для старих APK.

Офіційний репозиторій публікації: https://github.com/SergioYankovenko/svitlo/
Сайт: https://sergioyankovenko.github.io/svitlo/
Метадані: https://sergioyankovenko.github.io/svitlo/update.json

Механізм з’явився у версії 1.4.0. Старі встановлені версії 1.3.x не можуть отримати це повідомлення: спочатку користувач має встановити 1.4.0 звичайним способом. Після цього застосунок може повідомляти про наступні випуски.

Перевіряється опублікований файл версії з готовим APK. Коміт або зміна тексту сайту самі собою не створюють повідомлення. Порівнюється числовий `versionCode`, а не назва версії. Новий номер має бути більшим за попередній. Починаючи з 1.4.1, перевірка виконується автоматично раз на 24 години. У старих версіях цей інтервал помилково відраховувався також після невдалої спроби; нова 1.6.0 розділяє успіх та обмежені повтори. Перезапуск, зміна адреси або оновлення графіка не обходять інтервал успішної перевірки. Окремого блоку версії та ручної перевірки в опціях немає. Адреса та рахунок у запити GitHub не передаються.

Картка «Вийшла нова версія…» потрапляє у спільну стрічку за часом публікації, найновіші повідомлення зверху, строк показу — сім діб. За дозволу Android та ввімкнених сповіщень застосунок один раз показує системне повідомлення для кожного нового номера. Вимкнений дозвіл не заважає бачити картку. Зміна адреси не очищує стан версії. Завантаження відкривається у браузері; автоматичного встановлення немає.

## Публікація

1. Зібрати APK зі збільшеним `versionCode` і новою `versionName`, підписати тим самим сертифікатом, що попередню версію, перевірити тести й підпис.
2. Додати APK у репозиторій сайту за шляхом `downloads/Svitlo-<versionName>.apk`.
3. Додати або замінити `update.json` у корені сайту, бажано тим самим комітом. Використовувати фактичний час публікації, мінімальну версію Android та SHA256 готового APK.
4. Дочекатися успішного розгортання GitHub Pages. Перевірити HTTP 200 для JSON та APK, розмір APK і його SHA256. Перевірити, що JSON доступний як JSON, а не HTML-сторінка помилки.
5. На встановленій попередній версії з підтримкою перевірки дочекатися наступної добової фонової перевірки й перевірити повідомлення. Для відтворюваного тесту розкладу використовувати окремий емулятор і контрольований час; не змінювати номер у публічному JSON без відповідного готового APK.

Формат:

```json
{
  "schema": 1,
  "packageId": "ua.svitlo.widget",
  "versionCode": 12,
  "versionName": "1.4.2",
  "publishedAt": "2026-10-24T00:00:00Z",
  "minSdk": 26,
  "apkUrl": "https://sergioyankovenko.github.io/svitlo/downloads/Svitlo-1.4.2.apk",
  "sha256": "<64 hex-символи SHA256 готового APK>"
}
```

Приклад вище не є готовим файлом публікації. До пакета випуску додається окремий `update.json` із фактичним хешем. Якщо публікація відкладена, оновити `publishedAt` до фактичного часу, не вказуючи майбутній час.

Застосунок приймає лише HTTPS-посилання на очікуваний APK цього сайту, без перенаправлень у запиті JSON, стороннього домену, параметрів URL, чужого packageId або непідтримуваного minSdk. Некоректний/недоступний JSON не замінює попередні перевірені відомості. SHA256 у метаданих призначений для перевірки пакета під час публікації; застосунок передає завантаження браузеру й сам не перевіряє байти завантаженого APK. Android перевіряє сумісність підпису при встановленні поверх наявної версії.

Публікується лише пакет сайту: APK та JSON. Джерельний архів Android, приватні резервні копії, ключ підпису й пароль до нього не належать до публічного пакета сайту.
