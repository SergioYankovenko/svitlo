# Довідник черг: контракт для PWA та Android

Стан: **розгорнуто у production 24.10.2026** за окремим дорученням користувача. Таблиці, API, імпортер і розклад активні в проєкті `ovcmluucwzsuflusebcc` («Світло PWA»). Живий API підтвердив Флорештську, 10а/51 → 3.2 та Сичівку, Грушевського, 1 → 5.2; перший імпорт містить 58 правил з 12 PDF.

## Звернення клієнта

POST до чинної `svitlo-api`, JSON, `Authorization: Bearer <access_token>` анонімного Supabase-користувача та звичайний `apikey` проєкту. Секретний `service_role` у клієнт не передавати. Для вебзапитів діє перевірка дозволеного Origin; Android не підставляє вигаданий Origin.

Варіант із профілем цього користувача:

```json
{"action":"resolve_queue","id":"UUID профілю"}
```

Варіант без збереженого профілю:

```json
{
  "action":"resolve_queue",
  "address":{"department":"18","cityId":"801","streetId":"11807","house":"10а/51"}
}
```

Сервер перевіряє всі чотири значення через офіційні довідники. Назви населеного пункту й вулиці бере звідти. Літеру та дробовий номер не відкидає; місто й однойменне село не ототожнює. Цей варіант залежить від доступності офіційних довідників; довільні назви не приймаються як перевірена адреса.

Приклад відповіді (значення version і checkedAt залежать від імпорту):

```json
{
  "resolution": {
    "queue":"3.2",
    "status":"matched",
    "source":"official_registry",
    "scope":"street_all",
    "url":"URL офіційного PDF",
    "page":5,
    "version":"ідентифікатор набору PDF",
    "validUntil":"2027-04-01",
    "checkedAt":1790000000000
  }
}
```

Негативний результат: `queue:null`, status `unavailable`, `incomplete_address`, `not_found` або `ambiguous`. Це не підтвердження світла і не привід брати чергу сусіда. `unavailable` також означає, що чинної версії ще немає або строк її дії минув. Помилка запиту повертає HTTP-помилку; чужий профіль — 404, відсутній/нечинний сеанс — 401, перевищення частоти — 429.

`resolve_queue` шукає саме в реєстрі; він не замінює отримання графіка за особовим рахунком. У PWA при оновленні пріоритет має явна черга адресного API. Якщо реєстр суперечить їй, адресна черга зберігається, а `snapshot.queueResolution.conflict` містить номер із реєстру та версію для діагностики. Android має застосувати той самий пріоритет.

## Зберігання та імпорт

- `svitlo_queue_versions`: версії набору, чинність, час перевірки, SHA-256 PDF і розібрані публічні матеріали; активна лише одна версія.
- `svitlo_queue_rules`: правила активних/попередніх версій, підтвердження URL/сторінка. Прямий доступ anon/authenticated закритий; читання клієнта лише через перевірений API.
- Поточний консервативний імпортер підтримує однозначно названі цілі вулиці та цілі села. Діапазони будинків, частини вулиць, підприємства та інші складні конструкції **не перетворюються на приблизні правила**. Це не повне покриття області.
- Під час читання офіційних 12 PDF локальний прогін отримав 58 таких правил: Флорештська — 3.2 на рівні всієї вулиці; Сичівка — 5.2 на рівні села. Окремого рядка будинку 10а/51 у PDF немає.
- Завантажуються всі 12 документів; черга і період беруться із заголовків самих PDF. Незмінений SHA-256 дозволяє використати попередній розбір.
- Перемикання версії атомарне. Неповний набір, неправильний період, різке скорочення правил чи збій зберігають попередню версію. Прострочена версія не визначає чергу.
- Успішна перевірка раз на 14 днів; за наближення кінця чинності — щодня. Підготовлений щоденний dispatcher перевіряє `nextCheckAt`, а не розбирає PDF щодня. При помилці діє backoff.

## Порядок розгортання

Виконано після окремого дозволу: застосовано `20261024144933_queue_registry.sql`; розгорнуто API/jobs/registry; виконано контрольний імпорт; перевірено одну активну версію й обидві адреси; увімкнено `registry-schedule.sql` із наявними Vault-секретами. Cron-функція приймає тільки POST із серверним `x-cron-secret`; цей секрет не належить клієнтам. Щоденний dispatcher о 02:17 UTC перевіряє `nextCheckAt`; наступний повний імпорт має відбутися після 14 діб. Базу створено через SQL Editor чинного проєкту; початкова схема також була встановлена через Dashboard і не мала таблиці історії CLI-міграцій.

Локальна перевірка: `npm test` (у тому числі справжній PostgreSQL у PGlite: міграції, RLS, rollback, розклад) та `npm run build`. Hosted Edge runtime виконав перший імпорт за приблизно 4 секунди. В API перевірено автентифікований пошук, відмову без JWT, захист імпортера без cron-секрету та відсутність прямого клієнтського доступу до таблиць. Запит із самої Android-збірки ще не перевірений.
