# Світло PWA

Вебверсія на основі Android 1.4.2, без віджетів. Публічна адреса: https://sergioyankovenko.github.io/svitlo/app/

## Користування

- iPhone: відкрити в Safari → Поділитися → На Початковий екран. Push потребує iOS 16.4+ та дозволу після натискання кнопки в опціях.
- Android: відкрити в Chrome → Встановити застосунок. Push вмикається окремо в опціях.
- Додати та підтвердити адресу. Сповіщення прив’язані до активної адреси; переключення змінює прив’язку.
- Офлайн доступна остання збережена копія. Для нових графіків, адрес і сповіщень потрібна мережа.
- Застосунок показує дані оператора, а не вимірює наявність напруги.

## Розробка

Node.js 22+; `npm ci`, `npm test`, `npm run build`, `npm run dev`.
Локально: http://localhost:4173/app/ . Локальний сервер використовує тимчасове сховище в пам’яті та справжнє джерело; перезапуск скидає тестові адреси. Windows-запуск використовує системне сховище сертифікатів Node.

`app/` — браузерний клієнт та спільна логіка часу/графіка. `server/` — адаптер джерела, профілі, черга сповіщень. `supabase/` — SQL та Edge Functions. `tests/` — регресійні перевірки й збережені публічні приклади джерела.

Збірка створює `dist/app/`, браузерний bundle `app/vendor/supabase.js`, версійований service worker та однофайлові Edge bundles в ігнорованій `.local/bundles/`. GitHub Pages публікує `app/` з main; перед комітом завжди виконати build. Android APK та кореневий сайт залишаються окремими.

## Сервер

Окремий Supabase-проєкт `svitlo`, ref `ovcmluucwzsuflusebcc`, організація «Світло PWA», eu-west-1.
Дані сайту/CRM зі старого облікового запису не використовуються.

1. Застосувати міграції `supabase/migrations/`.
2. Увімкнути Anonymous Sign-ins. Клієнт отримує окремий JWT; авторизація перевіряється Edge Function через `auth.getUser`.
3. `npm run keys` генерує VAPID та секрет cron у `.local/server-secrets.env`. Не комітити, не замінювати чинні VAPID-ключі без плану перепідписки клієнтів.
4. Додати env у Supabase Edge secrets. `ALLOWED_ORIGINS=https://sergioyankovenko.github.io`; server role ключ доступний тільки в середовищі Supabase.
5. Розгорнути `svitlo-api`, `svitlo-jobs` (CLI або bundles). Legacy gateway JWT verification вимкнено: API сам перевіряє користувацький JWT; jobs перевіряє довгий `x-cron-secret`.
6. У Vault додати `project_url` та `svitlo_cron_secret`; виконати `supabase/schedule.sql`.
7. Public URL і publishable key в `app/config.js` — публічні. Service-role, cron та VAPID private key ніколи не додаються в клієнт.

Усі п’ять таблиць мають RLS. Прямі права anon/authenticated відсутні. Читання та записи відбуваються через API з перевіркою власника, обмеженням запитів і до 10 адрес. У frontend не передаються особові рахунки та ПІБ із джерела. Користувач може видалити профілі та підписки в опціях.

Cron викликає jobs щохвилини. Профілі оновлюються приблизно щогодини, по 5 за запуск. Feed кешується на годину. Нагадування перевіряються для нещодавно оновлених профілів сторінками по 100. Перед масовим запуском потрібна навантажувальна перевірка квот і часу виконання. Черга має lease, ідемпотентний ключ, TTL та обмежені повтори; помилки 404/410 прибирають недійсну підписку. Доставка не є точним будильником і залежить від ОС та push-провайдера.

## Особливість TLS джерела

На момент перевірки cabinet.cherkasyoblenergo.com віддає неповний ланцюжок сертифікатів. `operatorFetch` додає перевірені публічні Sectigo intermediates і USERTrust root лише для цього hostname. Підписи та строки intermediates перевіряються WebCrypto; HTTPS і перевірка hostname залишаються увімкненими. `operator-chain.js` містить тільки публічні сертифікатні дані. Після виправлення ланцюжка оператором додаткові CA можна прибрати. Ніколи не застосовувати `ignoreCertificateErrors`.

## Моніторинг

Перевіряти Supabase Edge logs, `cron.job_run_details`, статуси `net._http_response`, кількість прострочених/повторних `svitlo_deliveries`. У безкоштовного Supabase діють обмеження квот та можливе призупинення проєкту; це не гарантія безперервної доставки.

Фізичні iPhone/Android та поведінка ОС в енергозбереженні потребують окремого приймального тесту. Браузерні й серверні перевірки описано в `PWA-TESTS.md`.
